                                     RELATÓRIO DE DESENVOLVIMENTO — RIVALS ARENA

 1. Introdução

O Rivals Arena é um projeto desenvolvido com o objetivo de criar uma plataforma voltada para jogadores que gostam de participar de competições e acompanhar seus resultados. A proposta é reunir em um único site recursos como campeonatos, partidas, rankings, perfis de jogadores e equipes.

O projeto foi desenvolvido por uma equipe dividida em diferentes áreas, e nós dois ficamos responsáveis pela parte de Tecnologia da Informação. Nossa participação foi voltada principalmente para o desenvolvimento do site, a criação de funcionalidades e a organização da parte técnica do sistema.

 2. Nossa participação no projeto

Durante o desenvolvimento do Rivals Arena, ficamos responsáveis por trabalhar na parte técnica da plataforma. Utilizamos um site de referência para entender melhor a proposta e, a partir dele, trabalhamos na reconstrução e no aprimoramento do sistema.

Uma das nossas principais atividades foi organizar as páginas do site e desenvolver funcionalidades para que os usuários pudessem navegar pela plataforma e acessar seus diferentes recursos.

Também trabalhamos na programação, utilizando JavaScript para criar interações e funcionalidades, além de organizar a comunicação entre o site e o servidor. Ao longo do desenvolvimento, procuramos melhorar a estrutura do código e deixar o sistema mais organizado.

 3. Desenvolvimento das funcionalidades

Durante essa etapa, trabalhamos em diferentes áreas da plataforma, entre elas:

- Cadastro e login: desenvolvimento do sistema de acesso dos usuários.
- Perfil: organização das informações dos jogadores e apresentação de suas estatísticas.
- Campeonatos: desenvolvimento de funcionalidades relacionadas à criação, consulta e inscrição em competições.
- Ranking: organização das informações e classificação dos jogadores.
- Partidas: criação da estrutura para agendamento, registro e confirmação de resultados.
- Times: desenvolvimento da estrutura de funcionalidades para equipes e gerenciamento de integrantes.
- Arsenal: preparação do catálogo para apresentar os itens disponíveis na plataforma.

Além dessas funcionalidades, também trabalhamos nas regras de funcionamento das competições, considerando situações como confirmação de resultados, empates e contestação de partidas.

 4. Tecnologias utilizadas

Para desenvolver o projeto, utilizamos algumas tecnologias que permitiram construir o site e organizar seu funcionamento.

O HTML foi utilizado para estruturar as páginas, enquanto o CSS ficou responsável pela parte visual. Já o JavaScript foi utilizado para criar as interações e funcionalidades.

Na parte do servidor, trabalhamos com Node.js e Express para organizar as rotas e a comunicação com o sistema. Também utilizamos o Supabase, que oferece recursos de autenticação e banco de dados, permitindo trabalhar com o cadastro de usuários e o armazenamento das informações.

Além disso, utilizamos o GitHub para guardar o código, acompanhar as alterações e organizar as versões do projeto.

 5. Organização e segurança do sistema

Outra parte importante do nosso trabalho foi cuidar da organização e da segurança da plataforma. Como o site possui cadastro, login e informações dos jogadores, precisamos considerar formas de proteger o acesso aos dados.

Trabalhamos com recursos de autenticação, controle de sessão e mecanismos para respeitar as permissões definidas no banco de dados.

Também realizamos uma análise das estruturas existentes no Supabase para verificar se estavam de acordo com o código desenvolvido. Durante essa análise, identificamos algumas diferenças entre o que o sistema esperava e o que já existia no banco. Por esse motivo, documentamos as alterações necessárias e deixamos algumas integrações para uma etapa de validação, evitando modificar informações sem ter certeza de que seria seguro.

6. Testes realizados

Após as implementações, realizamos testes para verificar se o código estava organizado e se as principais funcionalidades apresentavam o comportamento esperado.

Na última execução registrada, o comando `npm test` apresentou os seguintes resultados:

- 39 arquivos JavaScript verificados, todos com sintaxe válida.
- 8 páginas HTML verificadas.
- 59 testes automatizados aprovados.
- Nenhuma falha nos testes.

Esses testes nos ajudaram a identificar e corrigir problemas durante o desenvolvimento. Porém, é importante destacar que parte deles utiliza uma simulação do Supabase. Por isso, os resultados não significam que todas as funcionalidades já foram testadas e aprovadas no banco de dados real.

7. Organização dos arquivos e GitHub

Durante o projeto, também trabalhamos na organização dos arquivos e na atualização do código. Para isso, utilizamos o GitHub, onde registramos as alterações e organizamos as versões do sistema.

Essa organização facilitou o acompanhamento do desenvolvimento e permitiu manter um histórico das modificações realizadas.

Ao final dessa etapa, enviamos a versão atualizada para o repositório do projeto, mantendo os arquivos organizados e a documentação disponível para consulta.
 8. Considerações finais

Participar do desenvolvimento do Rivals Arena foi uma oportunidade de colocar em prática os conhecimentos adquiridos durante o curso de Desenvolvimento de Sistemas.

Ao longo do projeto, tivemos contato com diferentes etapas do desenvolvimento de um sistema, desde a organização das páginas até a criação de funcionalidades, comunicação com o servidor, autenticação e integração com banco de dados.

Também percebemos que desenvolver uma plataforma envolve muito mais do que fazer o site funcionar visualmente. É necessário pensar na organização do código, na segurança das informações, nas regras de funcionamento e nos testes.

Apesar de algumas integrações ainda dependerem de validação no banco de dados real, consideramos que houve uma evolução importante na estrutura do Rivals Arena. O trabalho também contribuiu para ampliar nossos conhecimentos, melhorar nossa experiência com programação e entender melhor como funciona o desenvolvimento de um sistema na prática.
